# WSL 개발과 회사망 테스트의 진단 피드백

2026-10-09 설계 인터뷰에서 현재 Windows 개발 PC에서 WSL로 SSH 접속해 개발하고, 실제 회사망에서 별도로 테스트하기로 결정했다. 회사망 테스트의 상세 로그와 피드백을 개발 PC로 가져와 분석하고 구현을 수정한다. WSL 개발 환경에서의 성공과 회사 CLI에서의 호환성 검증 결과는 구분한다.

평상시 예제 앱은 연결 설정과 세션 식별정보를 저장하고, 대화와 원격 출력은 화면에 필요한 동안 메모리에서 사용한다. 대화와 원격 출력의 영구적인 로컬 복제를 기본 동작으로 삼지 않는다. 따라서 원격 기록을 바탕으로 재접속 후 내용을 복원할 수 있는지는 실제 CLI에서 확인해야 한다.

회사망 테스트는 상세 진단 기록을 남기는 별도 사용 흐름이다. 평상시의 로컬 기록 최소화 원칙이 테스트에 필요한 관측 자료의 수집을 막아서는 안 된다. 진단 모드는 상태·오류 로그와 함께 CLI 원문 출력, ANSI 제어문자, 수신 순서·분할 경계·시간, SDK가 해석한 질문, 사용자 응답과 전달 상태, 관찰 대상 세션 파일의 읽기 결과를 수집한다. SSH 자격 증명과 인증 비밀은 수집 대상에서 제외하고, 반출용 사본에서 내용을 확인하고 가림 처리할 수 있게 한다.

가져온 진단 기록을 실제 SSH 연결 없이 SDK 해석 로직에 다시 입력하는 재생 도구를 첫 개발 범위에 포함한다. 회사에서 발생한 질문 누락·중복·화면 해석 오류를 개발 PC에서 분석하고 회귀 테스트로 남긴다. 기록 재생으로 확인한 수정과 실제 회사 CLI에서 다시 테스트한 결과를 구분한다. 보관 한도와 구체적인 반출 파일 형식은 구현 설계에서 정한다.

회사 Windows PC는 인터넷에 연결되어 있으므로 오프라인 실행 패키지를 필수 요구사항으로 두지 않는다. 회사 Windows PC의 인터넷 연결 여부로 원격 Linux의 인터넷 연결 여부나 회사 CLI의 기능을 추정하지 않는다.
