# 설치된 회사 CLI를 기준으로 지원

2026-10-12 이슈 #30 설계 인터뷰에서 회사에 설치된 CLI를 그대로 사용하는 것을 지원 목표로 결정했다. 공개 CLI로 교체하는 것을 기본 해결책으로 삼지 않고, 실제 회사 CLI의 실행 옵션·데이터 저장경로·기록 형식·상호작용을 관측해 SDK의 지원 방식을 정한다. 회사 CLI 자체를 수정하지 않으며, 공개 CLI 검증을 회사 호환성 검증으로 대신하지 않는다.

원격 Linux의 tmux 설치를 필수 조건으로 확정했다. 실행 유지와 현재 화면·커서 관측, 재연결 복구에 사용하는 tmux를 유지하며, 이슈 #30에 tmux 없는 실행 방식의 개발을 포함하지 않는다. tmux가 없으면 사전 점검에서 부족한 필수 조건으로 보고하고 작업 시작을 차단한다. SDK는 tmux를 자동 설치하지 않는다.

사용자가 입력한 원격 path는 작업 디렉터리다. 해당 위치에서 CLI를 실행하고, 경로가 없거나 디렉터리가 아니거나 접근할 수 없으면 원인을 구분한 오류를 표시한다. 오류를 해결하기 위해 SDK가 작업 디렉터리를 임의로 생성하지 않는다.

회사 CLI의 인증·설정·대화 기록은 해당 CLI의 기존 저장 방식을 그대로 사용한다. 작업 디렉터리와 CLI 저장영역을 구분하며, 회사 CLI 지원을 위해 `--data-dir`이나 인증 사본 준비를 강제하지 않는다. SDK가 기존 인증·설정을 복사하거나 변경하지 않고, SDK로 시작한 작업을 식별해 기록 조회·재연결·중단·재개를 관리한다. 기존 대화 파일을 SDK가 직접 수정하거나 삭제하지 않는다. SDK 제어 파일은 CLI 저장영역과 구분한다.

이 결정은 회사 CLI의 데이터 경로·기록 형식·상호작용이 현재 SDK와 호환된다는 뜻은 아니다. 실제 기본 저장경로·세션 형식·실행 식별 근거를 확인해야 하며, 확인되지 않은 내용을 공개 CLI의 형식으로 가정하지 않는다. 기존 공개 CLI의 격리 실행 경로와 이번에 합의한 회사 CLI 지원 목표를 구분한다.
